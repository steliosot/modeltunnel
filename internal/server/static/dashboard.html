Configuration Reference

Available configuration options:

Option Description
server.host Server bind address (default: 127.0.0.1)
server.port Server port (default: 8080)
upstreams.*.type Upstream type: ollama
upstreams.*.base_url Ollama API URL (default: http://127.0.0.1:11434)
policies.*.rate_limit Rate limit: 60/min, 1000/hour, etc.
keys.*.allowed_upstreams List of upstreams this key can access
Python Client

Ready-to-use Python code to connect to your modeltunnel instance.

Python OpenAI SDK 
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:8080/v1",
    api_key="your-api-key-here"
)

# List available models
models = client.models.list()
print(models)

# Chat completion
response = client.chat.completions.create(
    model="ollama/mistral:latest",
    messages=[{"role": "user", "content": "Hello!"}]
)

print(response.choices[0].message.content)

# Streaming response
for chunk in client.chat.completions.create(
    model="ollama/mistral:latest",
    messages=[{"role": "user", "content": "Tell me a story"}],
    stream=True
):
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

# Intent-based routing (automatically selects best model)
# Use "auto" model with X-Model-Intent header
response = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Write a Python function to sort a list"}],
    extra_headers={"X-Model-Intent": "code"}  # Routes to code-optimized model
)

# Available intents: plan, code, chat
# plan → deepseek-r1 (reasoning, strategy)
# code → qwen2.5 (programming, debugging)  
# chat → phi (fast conversation)

JavaScript OpenAI SDK 
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'http://127.0.0.1:8080/v1',
  apiKey: 'your-api-key-here'
});

async function main() {
  const response = await client.chat.completions.create({
    model: 'ollama/mistral:latest',
    messages: [{ role: 'user', content: 'Hello!' }]
  });
  
  console.log(response.choices[0].message.content);
}

// Intent-based routing (automatically selects best model)
// Use "auto" model with X-Model-Intent header
async function codeTask() {
  const response = await client.chat.completions.create({
    model: 'auto',
    messages: [{ role: 'user', content: 'Write a Python function' }],
    headers: { 'X-Model-Intent': 'code' }  // Routes to code-optimized model
  });
  
  console.log(response.choices[0].message.content);
}

// Available intents: plan, code, chat
// plan → deepseek-r1 (reasoning, strategy)
// code → qwen2.5 (programming, debugging)
// chat → phi (fast conversation)

Installation

                        
                        
One-Line Installer (Recommended)

                        
Interactive wizard that installs Ollama + Modeltunnel with a guided setup:

                        

                            

                                Terminal
                                
                            

                            
curl -fsSL https://raw.githubusercontent.com/steliosot/modeltunnel/main/install.sh | bash

                        

                        
                        
For non-interactive / server installation:

                        

                            

                                Terminal
                                
                            

                            
curl -fsSL https://raw.githubusercontent.com/steliosot/modeltunnel/main/install.sh | bash -s -- --silent

                        

                        
                        
This will:

                        
    
                            
  • Check your system (OS, architecture, dependencies)
    • 
                            
  • Install Ollama (optional - you can skip if already installed)
    • 
                            
  • Install Modeltunnel
    • 
                            
  • Configure ports and directories
    • 
                            
  • Install recommended AI models
    • 
                            
  • Set up systemd service (Linux)
    • 
                        

                        
                        
Supports: Ubuntu, Debian, CentOS, macOS (Intel & Apple Silicon)

                        
                        
Installer options:

                        
    
                            
  • --silent - Non-interactive mode (installs modeltunnel only)
    • 
                            
  • --with-ollama - Also install Ollama
    • 
                            
  • --install-dir - Installation directory (default: /usr/local/bin)
    • 
                            
  • --help - Show all options
    •

Updating Modeltunnel

                        
Safely update Modeltunnel while preserving your configuration, API keys, and tunnel settings.

                        
                        
One-Command Update

                        
Run this single command to update to the latest version:

                        
                        

                            

                                Terminal
                                
                            

                            
curl -fsSL https://raw.githubusercontent.com/steliosot/modeltunnel/main/update.sh | sudo bash

                        

                        
                        
What Gets Preserved

                        
    
                            
  • ~/.config/modeltunnel/config.yaml - Your server configuration
    • 
                            
  • ~/.config/modeltunnel/keys.db - All your API keys
    • 
                            
  • ~/.config/modeltunnel/tunnel.url - Your tunnel settings
    • 
                        

                        
                        
What Gets Updated

                        
    
                            
  • /usr/local/bin/modeltunnel - The binary only
    • 
                        

                        
                        
Manual Update Steps

                        
If you prefer manual control:

                        

                            

                                Terminal
                                
                            

                            
# 1. Download update script
curl -O https://raw.githubusercontent.com/steliosot/modeltunnel/main/update.sh

# 2. Make it executable
chmod +x update.sh

# 3. Run the update
sudo ./update.sh

                        

                    
                    

                        
Docker

                        
Run modeltunnel in a container for easy deployment and isolation.

                        
                        
Using Docker Compose (Recommended)

                        
Docker Compose provides Modeltunnel with an integrated Ollama backend and persistent model storage. This is the easiest way to get started.

                        
                        
Quick Start

                        

                            

                                Terminal
                                
                            

                            
git clone https://github.com/steliosot/modeltunnel.git
cd modeltunnel
docker-compose up -d

                        

                        
                        
This starts:

                        
    
                            
  • Ollama on port 11434 (for model storage and execution)
    • 
                            
  • Modeltunnel on port 8080 (API and dashboard)
    •

Model Persistence

                        
Models persist in the ollama_data volume across container restarts. No need to re-download models after restarting.

# Restart services
docker-compose restart modeltunnel

Configuration

                        
modeltunnel uses a YAML configuration file located at ~/.config/modeltunnel/config.yaml

                        
                        
Example Configuration

                        

                            

                                YAML
                                
                            

                            
server:
  host: 127.0.0.1
  port: 8080

upstreams:
  default:
    type: ollama
    base_url: http://127.0.0.1:11434
    model: mistral

policies:
  default:
    rate_limit: 60/min
    max_tokens: 4096
  student-policy:
    rate_limit: 60/min        # default for all models
    max_tokens: 4096
    models:                   # model-specific overrides
      mistral:
        rate_limit: 5/min     # stricter limit for expensive model
        max_tokens: 2048
      phi:
        rate_limit: 100/min   # generous limit for fast model
        max_tokens: 1024
      tinyllama:*:            # wildcard matching
        rate_limit: 200/min

keys:
  - name: alice
    key: mt_sk_alice_xxx...
    allowed_upstreams: ["default"]
    policy: student-policy

                        

                        
                        
Per-Model Rate Limiting

                        
You can configure different rate limits and token limits for each model. This is useful when you want to restrict access to expensive models while allowing more usage of smaller, faster models.

                        
                        

                            

                                Model-Specific Configuration
                                
                            

                            
policies:
  student-policy:
    rate_limit: 60/min        # default for all models
    max_tokens: 4096
    models:
      # Exact model name match
      mistral:
        rate_limit: 5/min
        max_tokens: 2048
      
      # Base name match (matches mistral:latest, mistral:7b, etc.)
      phi:
        rate_limit: 100/min
        max_tokens: 1024
      
      # Wildcard match (matches tinyllama:latest, tinyllama:1.1b, etc.)
      tinyllama:*:
        rate_limit: 200/min

                        

                        
                        
Configuration Options

                        

                            
                                

                                    Option
                                    Description
                                    Default
                                

                            
                            
                                

                                    server.host
                                    Server bind address
                                    127.0.0.1
                                

                                

                                    server.port
                                    Server port
                                    8080
                                

                                

                                    upstreams.*.type
                                    Upstream type (ollama)
                                    required
                                

                                

                                    policies.*.rate_limit
                                    Default rate limit (requests/time)
                                    60/min
                                

                                

                                    policies.*.models.*.rate_limit
                                    Per-model rate limit
                                    inherits from parent
                                

                                

                                    policies.*.models.*.max_tokens
                                    Per-model max tokens
                                    inherits from parent
                                

                                

                                    keys.*.allowed_upstreams
                                    Upstreams this key can access
                                    [] (all)

Key Management Examples

                        

                            

                                CLI Examples
                                
                            

                            
# Create a key with default settings
modeltunnel key create alice

# Create a key with custom rate limit
modeltunnel key create bob --rate 100/min

# List all keys

# Revoke a key
modeltunnel key revoke alice

The web dashboard provides a visual interface for managing your modeltunnel instance. Access it at http://localhost:8080/admin (or your configured host:port).

                        
                        
Features

                        
    
                            
  • Overview: View connection URLs, server status, and quick start guide
    • 
                            
  • API Keys: Create, view, and revoke API keys with visibility controls
    • 
                            
  • Configuration: Edit YAML configuration directly in the browser with validation
    • 
                            
  • Request Logs: Monitor API requests in real-time via WebSocket
    • 
                            
  • Documentation: Access this documentation page
    • 
                        

                        
                        
Hot Reload

                        
The dashboard supports hot-reloading configuration changes. When you edit the YAML configuration and save, changes are applied immediately without restarting the server.

                    

                    
                    

                        
API Integration

                        
modeltunnel provides an OpenAI-compatible API, making it compatible with any client that supports the OpenAI API format.

                        
                        
Model Naming Convention

                        
Models are referenced using the format upstream/model:tag. For example:

                        
                        

                            

                                Model Names
                                
                            

                            
# Full format with upstream, model, and tag
ollama/mistral:latest
ollama/phi:latest
ollama/tinyllama:latest
ollama/qwen2.5:latest
ollama/deepseek-r1:latest

# Without tag (uses latest)
ollama/mistral
ollama/phi

# With specific version
ollama/mistral:7b
ollama/phi:2.7b

                                Python
                                
                            

                            
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8080/v1",
    api_key="your-api-key-here"
)

response = client.chat.completions.create(
    model="ollama/phi:latest",
    messages=[{"role": "user", "content": "Hello!"}]
)
print(response.choices[0].message.content)

Async Jobs

                        
Modeltunnel supports asynchronous model requests. Submit a job and get a job_id immediately, then poll for results later. Perfect for long-running requests, batch processing, or when you don't want to block the client.

                        
                        
When to Use Async

                        
    
                            
  • Long-Running Requests: Tasks that take more than 10 seconds
    • 
                            
  • Batch Processing: Process multiple items without blocking
    • 
                            
  • Unreliable Networks: Client may disconnect, job continues
    • 
                            
  • Background Tasks: Generate reports, summaries, analysis
    • 
                            
  • High Latency Tolerance: User doesn't need immediate response
    • 
                        

                        
                        
Submit Async Job

                        

                            

                                cURL
                                
                            

                            
curl -X POST http://localhost:8080/v1/async \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ollama/phi:latest",
    "messages": [{"role": "user", "content": "Write a story"}],
    "max_tokens": 500
  }'

                        

                        
                        
Response:

                        

                            
{
  "job_id": "job_1770736516577382000",
  "status": "queued"
}

                        

                        
                        
Check Job Status

                        

                            

                                cURL
                                
                            

                            
curl http://localhost:8080/v1/jobs/job_1770736516577382000 \
  -H "Authorization: Bearer YOUR_API_KEY"

                        

                        
                        
Python Example with Polling

                        

                            

                                Python
                                
                            

                            
import requests
import time

API_KEY = "mt_sk_user_abc123"
BASE_URL = "http://localhost:8080"

# Submit async job
response = requests.post(
    f"{BASE_URL}/v1/async",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "model": "ollama/phi:latest",
        "messages": [{"role": "user", "content": "Hello"}]
    }
)
job_id = response.json()["job_id"]

# Poll for completion
while True:
    status = requests.get(
        f"{BASE_URL}/v1/jobs/{job_id}",
        headers={"Authorization": f"Bearer {API_KEY}"}
    ).json()
    
    if status["status"] == "completed":
        print("Result:", status["result"]["choices"][0]["message"]["content"])
        break
    elif status["status"] == "failed":
        print("Error:", status["error"])
        break
    
    time.sleep(1)

                        

                        
                        
Job Status Values

                        

                            
                                

                                    Status
                                    Description
                                

                            
                            
                                

                                    queued
                                    Job is waiting in queue
                                

                                

                                    running
                                    Job is being processed
                                

                                

                                    completed
                                    Job finished successfully (result available)
                                

                                

                                    failed
                                    Job failed (error message available)
                                

                            
                        

                        
                        

                            ⚡ Implementation Details:
                            
    
                                
  • In-memory queue (1000 jobs max)
    • 
                                
  • 3 concurrent workers
    • 
                                
  • 120 second timeout per job
    • 
                                
  • Jobs lost on server restart
    • 
                            

                        

                    

                    
                    

                        
Intent-Based Model Routing

                        
Modeltunnel's intent-based routing automatically selects the best model for your task. Instead of manually choosing models, send an X-Model-Intent header and let the system optimize for your use case.

                        
                        
Configure Intents (Optional)

                        
Customize intent routing by editing your ~/.config/modeltunnel/config.yaml file:

                        
                        

                            

                                YAML
                                
                            

                            
intents:
  plan:
    priority:
      - deepseek-r1:latest
      - qwen2.5:latest
      - mistral:latest
    temperature: 0.3
    max_tokens: 4000
    description: "Planning, strategy, reasoning"
  
  code:
    priority:
      - qwen2.5:latest
      - mistral:latest
      - phi:latest
    temperature: 0.2
    max_tokens: 2000
    description: "Programming, debugging, technical"
  
  chat:
    priority:
      - phi:latest
      - tinyllama:latest
      - mistral:latest
    temperature: 0.7
    max_tokens: 1000
    description: "General chat, Q&A, support"

                        

                        
                        
Note: If no intents section is defined in your config, default intents are used automatically.

                        
                        
Available Intents

                        

                            
                                

                                    Intent
                                    Best For
                                    Routes To
                                

                            
                            
                                

                                    plan
                                    Strategy, architecture, reasoning
                                    deepseek-r1 → qwen2.5 → mistral
                                

                                

                                    code
                                    Programming, debugging, technical
                                    qwen2.5 → mistral → phi
                                

                                

                                    chat
                                    Conversation, Q&A, support
                                    phi → tinyllama → mistral
